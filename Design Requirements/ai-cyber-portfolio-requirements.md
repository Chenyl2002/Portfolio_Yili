# AI 视觉叙事作品集网站需求文档

## 1. 项目概述

本项目目标是制作一个接近参考视频风格的个人作品集网站：以原创角色、赛博/Y2K 视觉、AI 动画短片、HUD 界面和滚动穿梭动效为核心，让作品集不再只是传统信息排版，而像一段可交互的个人品牌 PV。

网站需要服务于求职与作品展示，因此视觉可以强烈，但核心信息必须清晰：用户应在 30 秒内理解“我是谁、我会什么、我做过哪些项目、如何联系我”。

## 2. 参考方向拆解

参考视频的核心不是单纯的 3D 技术，而是以下几层组合：

- AI 生成角色与场景动画：原创 OC、赛博背景、镜头推进、氛围光效。
- 网页式 HUD UI：导航、状态条、按钮、任务弹窗、标签、进度信息。
- 游戏化作品集结构：像进入一个角色档案、任务系统或互动界面。
- 滚动触发镜头：通过鼠标滚动制造“穿梭”“切换场景”“进入项目”的感觉。
- 前端包装与动效编排：把视频、图片、文字和 UI 叠加成一个可浏览网站。

## 3. 制作步骤

### 阶段 1：内容整理

整理现有作品集中的核心信息：

- 姓名、定位、求职方向。
- 个人简介与核心优势。
- 代表项目 3-5 个。
- 每个项目的标题、类型、职责、工具、亮点、成果、PDF 或图片入口。
- 简历信息、教育经历、技能栈、联系方式。

输出物：内容清单、项目排序、每个项目的一句话卖点。

### 阶段 2：视觉设定

确定网站的原创角色与世界观包装：

- 角色身份：游戏关卡 / 叙事策划候选人。
- 视觉关键词：赛博、Y2K、游戏 HUD、二次元角色、任务界面、作品集 OS。
- 主色调：深色背景，蓝紫霓虹光，少量高饱和点缀色。
- 页面语气：专业但有游戏感，避免过度“纯娱乐化”。

输出物：Moodboard、角色设定、首页静帧草图、字体与颜色规范。

### 阶段 3：AI 资产生成

生成或制作以下关键素材：

- 首页主视觉：角色 + 赛博环境 + 大标题区域。
- 角色动画：轻微呼吸、转身、眼神、衣服/发丝动效。
- 场景动画：背景粒子、光线流动、镜头推进。
- 穿梭动画：滚动后进入项目世界或任务界面。
- 项目展示背景：每个项目可有一张专属视觉图。

建议流程：

1. 先用静态图确定风格。
2. 再用图生视频生成 3-5 秒循环片段。
3. 最后用前端控制片段切换、遮罩、淡入淡出和滚动进度。

### 阶段 4：网页原型设计

用 Figma 或直接前端搭建页面结构：

- 第一屏必须展示角色、姓名、定位和主要行动按钮。
- 项目区域要能清楚阅读，不能被视觉特效淹没。
- 简历与联系区域要保持高可读性。
- 手机端需要单独设计简化版，不强行保留全部桌面动效。

输出物：首页高保真稿、项目详情稿、移动端稿。

### 阶段 5：前端开发

推荐技术方案：

- 框架：Next.js 或 Vite + React。
- 样式：Tailwind CSS 或现有 CSS 体系。
- 动效：GSAP + ScrollTrigger，或 Framer Motion。
- 视频：WebM/MP4 背景视频，必要时提供静态 fallback。
- 3D：只有在需要实时交互时使用 Three.js，否则优先用预渲染视频。
- 部署：Vercel、Netlify 或 GitHub Pages。

核心原则：优先实现稳定、可读、可部署的网站，再逐步增强高级动效。

### 阶段 6：性能与验收

上线前检查：

- 首屏加载速度。
- 视频大小与压缩。
- 移动端是否卡顿。
- 文字对比度是否足够。
- PDF、项目图片、联系方式是否可访问。
- 动效关闭或加载失败时，网站仍能完整浏览。

## 4. 页面结构

### 4.1 首页 Hero / Portfolio OS

目标：用最强视觉建立个人品牌。

内容：

- 姓名：陈宜理。
- 定位：Game Level & Narrative Planning / 游戏关卡与叙事策划。
- 一句话介绍。
- 主要按钮：查看项目、查看简历、联系我。
- 原创角色主视觉。
- HUD 装饰信息：年份、角色档案编号、技能标签、当前任务状态。

动效：

- 页面进入时出现加载动画。
- 角色与背景有轻微循环运动。
- 标题、标签、按钮分层淡入。
- 鼠标移动时可有轻微视差。

### 4.2 滚动穿梭转场

目标：复刻参考视频中“滚动鼠标进入另一个空间”的感觉。

内容：

- 鼠标滚动提示。
- 速度线、粒子、镜头推进、光圈或隧道视觉。
- 转场后进入项目界面。

实现建议：

- MVP：使用一段预渲染穿梭视频作为背景，滚动时淡入播放。
- 进阶：使用 GSAP 控制视频进度。
- 高级：使用 Three.js 做实时隧道与摄像机推进。

### 4.3 项目任务界面

目标：把作品展示包装成“任务列表 / 档案系统”。

内容：

- 项目筛选：全部、UE5、关卡设计、叙事设计、团队项目、个人项目。
- 项目卡片：标题、类型、职责、工具、亮点。
- 项目详情弹窗：背景、目标、玩法/关卡设计、个人贡献、成果、文档入口。
- PDF 预览或下载入口。

动效：

- 项目卡片 hover 时出现扫描线、发光边框或小幅位移。
- 打开详情时像系统面板展开。
- 切换项目时使用轻量过渡，不影响阅读。

### 4.4 角色档案 / 简历界面

目标：把简历包装成角色属性面板，但保留招聘可读性。

内容：

- Profile：头像、姓名、所在地、求职方向。
- Education：教育经历。
- Skills：UE5、关卡设计、叙事设计、空间设计、项目协作等。
- Experience：项目经历与奖项。
- Player Insight：游戏经历与类型偏好。

动效：

- 属性条或技能标签逐个加载。
- 时间线淡入。
- 重要技能可用高亮标签，但不要用过多装饰。

### 4.5 联系 / 结尾场景

目标：给访问者明确行动出口。

内容：

- 邮箱。
- Bilibili / LinkedIn / GitHub / 其他主页。
- 简历 PDF 下载。
- 合作、实习、校招机会说明。

动效：

- 可以使用任务完成、通讯连接、系统登出等包装。
- 结尾画面应稳定，方便复制联系方式。

## 5. 功能需求

### 必须实现

- 首页主视觉与个人定位。
- 项目列表与项目详情。
- PDF 文档预览或下载。
- 简历信息区域。
- 联系方式区域。
- 桌面端与移动端适配。
- 基础滚动动效。

### 建议实现

- AI 视频背景或短循环动效。
- HUD 装饰层。
- 项目筛选。
- 页面加载动画。
- 轻量视差。
- 滚动穿梭转场。

### 可后续增强

- Three.js 实时场景。
- 音效开关。
- 游戏式任务系统。
- 角色对话弹窗。
- 访客可选择不同作品集路线。

## 6. 非功能需求

- 首屏在正常网络下应尽快可见，视频素材延迟加载。
- 所有核心文字必须是 HTML 文本，不能只放在图片里。
- 视频加载失败时显示静态海报图。
- 移动端关闭复杂穿梭或 3D 效果，保留叙事顺序。
- 保持基础 SEO：标题、描述、项目关键词。
- 保持可访问性：按钮有清晰文本，颜色对比足够。

## 7. 资产清单

### 角色资产

- 原创角色正面立绘。
- 角色半身图或头像。
- 角色动态视频：3-5 秒循环。
- 透明背景版本。

### 场景资产

- 首页赛博背景。
- 项目界面背景。
- 穿梭转场视频。
- 结尾联系场景。

### UI 资产

- HUD 边框。
- 圆形按钮。
- 任务弹窗。
- 项目卡片背景。
- 标签、状态条、扫描线纹理。

### 内容资产

- 项目图片。
- 项目 PDF。
- 简历 PDF。
- 联系方式链接。

## 8. 技术实现建议

### MVP 方案

适合最快做出接近效果的版本。

- 使用现有 HTML/CSS/JS 或 React。
- 首页用 AI 静态图 + CSS 动效。
- 穿梭动画用视频。
- 项目区和简历区用常规 HTML 卡片。
- 使用 GSAP 做滚动触发和过渡。

优点：稳定、开发快、部署简单。

### 进阶方案

适合做成更像参考视频的版本。

- 使用 Next.js。
- 使用 GSAP ScrollTrigger 控制视频进度。
- 使用 Framer Motion 做 UI 面板动效。
- 使用 WebM 视频和静态 fallback。
- 局部使用 Canvas/Three.js 做粒子、隧道或背景。

优点：视觉更接近参考，仍然可维护。

### 高级方案

适合追求实时交互和展示技术力。

- 使用 Three.js / React Three Fiber。
- 实时 3D 场景、摄像机路径、粒子隧道。
- 角色可使用 Live2D、Spine 或预渲染序列帧。

风险：开发周期长、性能压力大、移动端适配复杂。

## 9. 推荐开发优先级

### P0：可上线版本

- 完成内容结构。
- 完成首页视觉。
- 完成项目展示。
- 完成简历和联系。
- 完成基础响应式。

### P1：接近参考视频

- 加入 AI 动态背景。
- 加入 HUD 组件。
- 加入滚动穿梭。
- 加入项目详情弹窗。

### P2：高级体验

- 加入 Three.js 或 Canvas 粒子。
- 加入角色对话。
- 加入声音与开关。
- 加入更复杂的分支交互。

## 10. 验收标准

- 第一屏能明确看到“陈宜理”和求职定位。
- 网站整体风格接近赛博/Y2K/游戏 HUD，而不是普通作品集模板。
- 滚动后能产生明显的场景推进或穿梭感。
- 项目内容完整、可读、可点击查看详情。
- 简历信息能被招聘者快速扫描。
- 联系方式清楚，不被动效遮挡。
- 桌面端视觉完整，移动端无横向溢出。
- 视频或动画失败时，页面仍可正常阅读。
- 页面加载不应因为大视频长时间空白。
- 所有核心作品集信息都能在 3 次滚动内被用户找到。

## 11. 风险与注意事项

- 不要把所有文字做进图片或视频，否则不利于阅读、SEO 和后期修改。
- 不要过度依赖 Three.js；如果只是为了视觉氛围，视频背景更高效。
- AI 视频可能会有闪烁、角色变形、文字乱码，需要避免把关键文字交给 AI 生成。
- 招聘场景下，视觉冲击要服务于作品展示，不能让 HR 找不到项目和简历。
- 动效应有节制，核心区域停下来时必须能安静阅读。

## 12. 一句话制作路线

先做一个稳定可读的作品集网页，再用 AI 生成角色与场景素材，最后用滚动动效把它包装成“个人作品集 OS”的互动体验。
